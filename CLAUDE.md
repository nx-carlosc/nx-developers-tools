## What this is

A Chrome extension (Manifest V3) for Nexum developers with two tools:

1. **Domain Replacer** — swaps the origin of the current tab's URL with a stored domain. Domains are persisted via `chrome.storage.sync`.
2. **Git Branch Creator** — reads Jira ticket data from the active tab (via a content script) and generates a branch name from a user-defined template. Settings are stored per Jira project via `chrome.storage.sync`.

## Commands

```bash
npm run dev        # start Vite dev server
npm run build      # build extension to /dist
npm test           # run all tests once (Vitest)
npm run test:watch # run tests in watch mode
```

Run `npm run build` to produce `/dist`. Upload `/dist` to the Chrome Web Store to release.

## Architecture

Source lives in `/src`. Build output is `/dist` (gitignored, generated by `npm run build`).

**Entry points** (`vite.config.ts`):
- `popup.html` + `src/main.tsx` — React app entry (compiled to `dist/popup.html` + `dist/popup.js`)
- `src/jira-script.ts` — Content script entry (compiled to `dist/jira-script.js`, no React)

**Static assets** (`public/`, copied as-is to `dist/`):
- [public/manifest.json](public/manifest.json) — Manifest V3, requests `tabs`, `storage`, `activeTab` permissions. Injects `jira-script.js` on all URLs.
- [public/icon_128.png](public/icon_128.png) — extension icon

**React components** (`src/components/`):
- [src/components/DomainReplacer.tsx](src/components/DomainReplacer.tsx) — Domain Replacer UI. Reads/writes `chrome.storage.sync`. Replaces the active tab's origin and opens the new URL in a new tab.
- [src/components/BranchCreator.tsx](src/components/BranchCreator.tsx) — Branch Creator UI. Receives Jira data as props from `App.tsx`. Saves per-project `{ branchInputValue, charReplacerValue, typeValue }` in `chrome.storage.sync`.
- [src/components/TaskTimer.tsx](src/components/TaskTimer.tsx) — Task Timer UI. Stores tasks in `chrome.storage.local`. Uses the Temporal API for time formatting.

**Utilities** (`src/`):
- [src/App.tsx](src/App.tsx) — Root component. Fetches active tab, sends `"send-jira-data"` to content script, owns `JiraData` state passed to children.
- [src/jira-script.ts](src/jira-script.ts) — Content script. Handles `"send-jira-data"` message with three code paths: Atlassian modal URLs, Atlassian non-modal URLs, and legacy Jira selectors.
- [src/utils/branchNameCreator.ts](src/utils/branchNameCreator.ts) — Pure function that replaces `$0`/`$1`/`$2`/`$3` with type/project/ticket/title, then applies the character replacer. This is the only unit-tested module.
- [src/consts.ts](src/consts.ts) — `BRANCH_REGEXP` (invalid git branch characters), storage key names, `DEFAULT_BRANCH_TYPES`.

Tests in `/tests` use Vitest and import directly from `/src`.

## Branch name template syntax

The template uses positional placeholders: `$0` = type (user-selected), `$1` = project, `$2` = ticket, `$3` = title. Spaces and characters matching `BRANCH_REGEXP` are replaced with the user-supplied single-character divider. Consecutive divider characters are collapsed to one.

`$0` values come from a `<select>` populated from `DEFAULT_BRANCH_TYPES` (`feat`, `fix`, `hotfix`, `release`, `chore`, `docs`, `refactor`) merged with any custom types saved under `STORED_BRANCH_TYPES` in `chrome.storage.sync`. Types can be added with the `+` button or removed with the `−` button (disabled when only one type remains). The generated branch name is contenteditable — users can tweak it inline before clicking the copy icon.
